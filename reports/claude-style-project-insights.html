What This Project Is

The codebase is organized around a public portfolio viewer plus a local editor workflow. The intended artifact is a deployable static site.

Interactive career canvas

Desktop mode combines a canvas, sidebar, minimap, timeline rows, cards, connection lines, pan/zoom, skill highlighting, and detail modal behavior. The data model stores absolute card positions and sizes, so the portfolio behaves more like a mapped experience graph than a linear resume.

Mobile alternate experience

Mobile mode switches away from the canvas into a vertical card flow with tabs, visible language controls, skill filtering, and a detail drawer. That prevents the desktop canvas interaction model from being forced onto small screens.

Three-language content model

All display text is modeled as LocaleText with English, Simplified Chinese, and Traditional Chinese. The validation layer checks required localized fields before save and export.

Local editor, static viewer

Editor mode is gated by VITE_APP_MODE=editor. Public viewer builds do not mount the editor panel, while the editor server binds only to 127.0.0.1:5174 and writes portfolio JSON through validation, backup, and atomic rename.

Key pattern: data-heavy UI with small infrastructure surface

The largest file is the portfolio seed, not the app shell or server. The runtime code is concentrated in canvas behavior, cards, modals, editor UI, and transform hooks; the backend surface is only two local/export scripts.

Architecture

Data loading is explicitly ordered

Viewer mode reads embedded single-file export data first, then ./data.json, then bundled defaultPortfolio. Editor mode fetches /api/portfolio. That makes normal static export and single-file export first-class paths rather than afterthoughts.

Canvas behavior is isolated in hooks and components

useCanvasTransform owns pan, zoom, focus, reset, bounds fitting, and animation. Canvas owns container measurement, keyboard shortcuts, background drag, window focus helpers, and card rendering orchestration.

Public/editor separation is mostly compile-time

IS_EDITOR gates editor mounting, save hooks, card editing, and API calls. The local server validates payloads and writes with backup plus atomic rename.

Export pipeline is deployment-oriented

server/export-static.ts runs a viewer build, copies dist into dist-static, writes data.json, patches font URLs, and can inline CSS, JS, data, and fonts for a single-file artifact.

Automated regression coverage is thin

package.json has typecheck and lint, but lint aliases TypeScript checking and there is no npm test. Browser QA is documented but not automated here.

Font payload dominates static size

public/fonts is about 25M and dist-static is about 26M. This is acceptable for controlled sharing, but heavy for public portfolio hosting unless font coverage is required.

Static data freshness needs discipline

The viewer can use bundled seed or exported data.json. That flexibility is useful, but content updates should always run export validation so deployable data and source data do not drift.
